## 上游第十四批：Windows shell 探测跟随 `%SystemRoot%`（#9501/#9504 / `28bea006b`）

- 上游两半，端口只接一半：
  1. **`isLegacyWslBashPath` 不再写死 `C:\Windows`（已移植）**：`Pi.CodingAgent.Utils.Shell
     .IsLegacyWslBashPath(path, systemRoot = null)` 按 `%SystemRoot%` 拼 `System32`/`Sysnative`；
     `systemRoot` 缺失或**非盘符限定**（`\\server\share`、相对路径）退回约定形态正则——对应上游
     「未知 Windows 目录就按 `C:\Windows` 认」的兜底。`DriveQualifiedRegex` **必须带
     `RegexOptions.IgnoreCase`**，否则 `C:\Windows` / `D:\WINNT` 大写盘符匹配不上（实测踩过）。
  2. **Store 别名（不适用）**：上游把 `existsSync` 换 `accessSync(F_OK)`，因为 node 的 `existsSync`
     在 Windows 上额外 stat，让可执行的 Store 别名返回 EACCES。.NET 的 `File.Exists` 走
     `GetFileAttributesEx`，没有这个误判路径，维持原样；硬造访问检查反而引入要规避的问题。
- `Pi.Durable` 不引用 `Pi.CodingAgent`，`Env/LocalExecutionEnv.cs` 有同名私有方法，同步成同一语义，
  `GetBashShellConfig` 的 `-s`/`-c` 分支随之对齐。
- 测试：新建 `ShellProbeTests` 19 例（13 例覆盖约定形态/已知 SystemRoot/装在别处/非盘符 SystemRoot，
  6 例钉住只有 System32 与 Sysnative 命中）。`CoreUtilsCorpusTests` 那两条向量显式传
  `systemRoot: ""`，否则本机 `%SystemRoot%` 会让语料结果随机器变化。
- 验证：构建 0 警告 0 错误；CodingAgent 5009 / 5009（+19）、Durable 457 / 457。
- 台账：`docs/upstream-1.4.0-delta.md` §3.3 该行改「本次移植（第十四批，Store 别名部分不适用）」，
  新增 §6.q 明细，§5 验证结果与 §7 顺序同步。

## 上游第十五批：MCP OAuth 取消与关闭语义（f10993bc7 / #10565）

- 上游把 `AbortSignal` 加进整条 OAuth 链路；端口这一层本来就是 `CancellationToken`，所以落地是
  「补齐语义」而不是「加参数」。五处：
  1. `StreamableHttpTransport.CloseAsync`：DELETE 复用 `_lastToken`（`ApplyAuthHeaders` 新增 token 参数），
     超时只用独立 1s CTS，**不再链调用方令牌** —— `AuthProvider.Token()` 可能先做网络刷新，关闭不能等它。
  2. `OAuthFlow.RunFlowAsync` 刷新分支加 `catch (Exception) when (cancelled) { throw; }`：
     取消的刷新不得退化成新授权（refresh token 可能已轮转）。
  3. `OAuth.cs`：`RefreshRequestTimeoutMs` → `OAuthRequestTimeoutMs`；新增 `TimedFetch()`（TS `timedFetch`），
     刷新与登录共用；`SignInServerAsync` 进来先判取消，外层把任何「取消期间的异常」统一成
     `McpSignInCancelledError`（CLI 文案依赖这个类型）。
  4. `McpExtension`：删 `sessionActive`/`generation`，换成一个**初始即取消**的 `CancellationTokenSource`；
     新增 `Track(Task)` 登记管理动作与登录；`SessionShutdown` 先 `CancelAsync()` 再等登记的工作清理完；
     `SignInAsync` 多一个 `cancel` 参数（会话令牌 + Esc 令牌链接）；动作结束后检查会话是否已结束。
  5. `Cli.cs`：`--timeout` 从「等粘贴 URL」提到整次登录（`SignInServerAsync` 的令牌），
     `WaitForRedirectUrlAsync` 去掉自己的 timeoutMs。
- `IMcpUi.Status` 增加可选 `onCancel`；`McpManagerView` 有回调才显示 cancel 提示并响应 `tui.select.cancel`。
- 测试坑（重要）：`HttpListener` 前缀要挂**根**（`http://127.0.0.1:port/`）。发现请求打在
  `/.well-known/...`，用 `/mcp/` 前缀时 `GetContextAsync` 抛 404、服务循环直接 return，表现为客户端超时。
- 验证：构建 0 警告 0 错误；CodingAgent 5013 / 5013（+4）、Pi.Mcp 55 / 55（+3）、Ai 480 / 480、
  Durable 457 / 457（并行跑多套件时出现过 1 例偶发，单独连续两次全绿）。
