## 上游第十四批：Windows shell 探测跟随 `%SystemRoot%`（#9501/#9504 / `28bea006b`）

- 上游两半，端口只接一半：
  1. **`isLegacyWslBashPath` 不再写死 `C:\Windows`（已移植）**：`Pi.CodingAgent.Utils.Shell
     .IsLegacyWslBashPath(path, systemRoot = null)` 按 `%SystemRoot%` 拼 `System32`/`Sysnative`；
     `systemRoot` 缺失或**非盘符限定**（`\\server\share`、相对路径）退回约定形态正则——对应上游
     「未知 Windows 目录就按 `C:\Windows` 认」的兜底。`DriveQualifiedRegex` **必须带
     `RegexOptions.IgnoreCase`**，否则 `C:\Windows` / `D:\WINNT` 大写盘符匹配不上（实测踩过）。
  2. **Store 别名（不适用）**：上游把 `existsSync` 换 `accessSync(F_OK)`，因为 node 的 `existsSync`
     在 Windows 上额外 stat，让可执行的 Store 别名返回 EACCES。.NET 的 `File.Exists` 走
     `GetFileAttributesEx`，没有这个误判路径，维持原样；硬造访问检查反而引入要规避的问题。
- `Pi.Durable` 不引用 `Pi.CodingAgent`，`Env/LocalExecutionEnv.cs` 有同名私有方法，同步成同一语义，
  `GetBashShellConfig` 的 `-s`/`-c` 分支随之对齐。
- 测试：新建 `ShellProbeTests` 19 例（13 例覆盖约定形态/已知 SystemRoot/装在别处/非盘符 SystemRoot，
  6 例钉住只有 System32 与 Sysnative 命中）。`CoreUtilsCorpusTests` 那两条向量显式传
  `systemRoot: ""`，否则本机 `%SystemRoot%` 会让语料结果随机器变化。
- 验证：构建 0 警告 0 错误；CodingAgent 5009 / 5009（+19）、Durable 457 / 457。
- 台账：`docs/upstream-1.4.0-delta.md` §3.3 该行改「本次移植（第十四批，Store 别名部分不适用）」，
  新增 §6.q 明细，§5 验证结果与 §7 顺序同步。
