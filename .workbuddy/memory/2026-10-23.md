# 2026-10-23

## 发布 1.4.0 到 nuget.org

背景：代码已从 1.0.4 对齐到上游 Pi `1.4.0`（`CHANGELOG` 里原为 `[Unreleased]`，
含 11 条 upstream 1.1.0–1.4.0 backport，清单在 `docs/upstream-1.4.0-delta.md`），
但 `Directory.Build.props` 的 `<Version>` 还是 1.0.4。

### 做法（沿用 tag 触发）

1. `<Version>` 1.0.4 → **1.4.0**；`CHANGELOG` 的 `[Unreleased]` 内容提升为
   `## [1.4.0] - 2026-10-23`，并在段首补一句「Version alignment with upstream Pi 1.4.0」。
   保留一个空的 `## [Unreleased]` 头（Keep a Changelog 惯例）。
2. 发布前本地闸门：`dotnet pack Pi.slnx -c Release -p:Version=1.4.0`
   → 13 nupkg + 13 snupkg，`Pi.Cli/Pi.Vacation/Pi.DurableHost/Pi.Evals` 无误打包；
   nuspec 与程序集版本都读 1.4.0；`Pi.CodingAgent` 仍是 14 个 contentFiles。
3. 测试冒烟（CI 不跑测试，这几项自测）：`Pi.Ai` 435、`Pi.Agent`、`Pi.Mcp`、`Pi.Protocol` 全绿。
   `Pi.Ai.Tests` 第一次跑有 1 例失败，随后两次复跑均 0 失败 → 判定为 flake（时间敏感类型），
   不是回归。`Pi.Tui` / `Pi.Env` 仍需真实终端 / 本地 sshd，CI 与本地都不跑。
4. `chore(release): 1.4.0` → 打 annotated tag `v1.4.0` → `git push origin main refs/tags/v1.4.0`
   一次推完分支与标签。
5. 发布工作流 `39894735415`（约 4 分钟）成功；同时触发的 `main` CI `39894735992` 也成功。

### 发布后核对（都验过）

- GitHub Release **Pi.NET 1.4.0**：非 draft、非 prerelease，13 个 nupkg 资产齐全。
- nuget.org：13 个包 nuspec 与 nupkg 全部 200 可下载；
  `pi.ai` / `pi.codingagent` 的 index.json 都出现 `1.4.0`。
  `pi.codingagent` 的 nuspec 里 `repository commit="ad0f2405f9…"` 与 tag 指向的提交一致。
- 消费者实测：全新 console 工程 `dotnet add package Pi.CodingAgent --version 1.4.0`
  → restore + build 0 警告 0 错误，`bin/…/Assets` 下落地 14 个运行时资源。
  （顺便记一下：判断包是否已上线要用 `curl -L`，裸请求会拿到 302 而不是 200；
  另外 flatcontainer 的 nupkg 路径必须是 `<id>/<ver>/<id>.<ver>.nupkg`，漏掉版本段会 404。）

### 需要注意

- tag `v1.4.0` 钉在 `ad0f240`（发布提交）。之后 `main` 上又多了 `7af7783`
  （`docs: generate the models.json field reference`，并行工作线提交并已推送），
  与发布无关，不需要重新发版。
- 重复发布不可行：NuGet 同版本号不可覆盖，后续修复只能发 1.4.1。
