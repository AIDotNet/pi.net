## 第二轮自查 + 42 家模型目录（提交 8c8b489）

### 自查修掉的三处

1. `ImageMime.ImageDimensions` 返回值用 `int`：PNG 宽高是 uint32，超过 `int.MaxValue` 会截成负数，
   `-1 > 2000` 为假 → 超大图**绕过**像素限制。改成 `long`，`ImageSize` 一并改，加回归
   `Read_PngWithHugeDimensions_IsRejected`（4000000000×4000000000）。
2. `TelemetryRender.RenderTrace` 对重复 span id 会渲染成两行；上游是 `Map` 语义（位置取首次、
   值取最后一次）。改成显式去重 + 稳定排序，加回归。
3. **`azure` 的 provider id 是上游已废弃的旧名** `azure-openai-responses`（上游 CHANGELOG 明确
   记了改名，要求同步 `auth.json` / `models.json` / `settings.json`）。后果：`defaultProvider: "azure"`
   找不到 provider、配置失配、`azure.json` 目录永远加载不到。改成 `azure`，
   `ModelCatalog._knownProviders` 同步。

### 42 家数据：结论是「能加，而且必须加」

- 原台账 §6 第 4 条判「不适用」的理由（data 被 gitignore、需要本地 models.all.json）都成立，
  但漏了 **`packages/ai/package.json` 的 `build:offline` 会把 `src/providers/data` 复制进 `dist`**。
  所以 npm 包 `@earendil-works/pi-ai@1.4.0` 自带 42 份数据 —— 从 `dist/providers/data/` 原样取即可，
  不用编造、不用访问 42 家 API。注意连 `.manifest.json` 一起取（`GetBuiltinModelDataGeneratedAt`
  读 `Pi.Ai.ModelData..manifest.json`；MSBuild 的 `ModelData\*.json` 能匹配隐藏文件）。
- **为什么是必须**：`ModelResolver.DefaultModelPerProvider` 41 条是上游新 id（gpt-5.5 /
  claude-opus-4-8 / deepseek-v4-pro …），而端口目录只有 3 个手写文件、8 个旧模型（gpt-4o 等）。
  核对结果：**41 条默认模型一条都解析不到**，全新安装遍历完整张表也选不出模型。
- 落地：42 份 JSON + manifest（1.1MB 嵌入资源），条目 8 → 1713。openai 42 chat + 1 classifier、
  openrouter 401 chat + 63 image + 28 classifier、anthropic 17、radius 32 基线。
- 未识别字段（enabled / lab / providers / output / promptCache / free）进 `Extra` —— 上游
  `model-catalog.ts` / `models.ts` / `radius.ts` 同样不消费，无行为差异。
- 10 处测试断言从「数据缺失状态」改成上游事实；新增两条守护
  `EveryEmbeddedCatalogParses`、`EveryDefaultModelResolvesInTheBuiltinCatalog`。

### 2. durable 内置图片处理器

- **踩坑**：`ImageResizeCore` 的快路径只看尺寸与字节、不看格式，BMP 会被原样透传。加
