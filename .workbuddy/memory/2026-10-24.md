## 第二轮自查 + 42 家模型目录（提交 8c8b489）

### 自查修掉的三处

1. `ImageMime.ImageDimensions` 返回值用 `int`：PNG 宽高是 uint32，超过 `int.MaxValue` 会截成负数，
   `-1 > 2000` 为假 → 超大图**绕过**像素限制。改成 `long`，`ImageSize` 一并改，加回归
   `Read_PngWithHugeDimensions_IsRejected`（4000000000×4000000000）。
2. `TelemetryRender.RenderTrace` 对重复 span id 会渲染成两行；上游是 `Map` 语义（位置取首次、
   值取最后一次）。改成显式去重 + 稳定排序，加回归。
3. **`azure` 的 provider id 是上游已废弃的旧名** `azure-openai-responses`（上游 CHANGELOG 明确
   记了改名，要求同步 `auth.json` / `models.json` / `settings.json`）。后果：`defaultProvider: "azure"`
   找不到 provider、配置失配、`azure.json` 目录永远加载不到。改成 `azure`，
   `ModelCatalog._knownProviders` 同步。

用户问「pi.net 是否和 pi 一样具备扩展插件」。查下来**结论要分两层**。

### 能力面确实对齐

- `IExtensionApi` 31 个注册/查询方法 + `On<E>`/`On<E,R>` 事件订阅，与上游 1:1。
- 事件 41 个，逐个在上游 `types.ts` 里命中，零缺失。
- 三层发现（`.pi/extensions` → `<agentDir>/extensions` → settings 路径）、`package.json` 的
  `pi.extensions` manifest、collectible ALC（可 `Unload` 真卸载，比 TS 清 module cache 更强）。
- 扩展测试 434 例。

### 但默认路径下加载必然失败（本轮最重的发现）

`ExtensionLoader` 在调用方不给 `moduleLoader` 时落到 `MissingModuleLoader`（4d-2b 的占位），
直接抛「no IExtensionModuleLoader was supplied… lands with batch 4d-3」。而 4d-3 的
`AssemblyLoadContextExtensionLoader` 早写好了，**默认值忘了换**。`ResourceLoader` 的两处
`LoadExtensionsCached(...)` 都没传 loader → 任何真实扩展都加载不了（内置扩展走
`BuiltInExtensions`，不受影响）。

修复：默认 `AssemblyLoadContextExtensionLoader.Instance`（进程内单例，保住按路径复用的 context），
占位类删除。验证：临时项目加载示例 dll，修复前 `errors=1`（就是那句占位错误），修复后
`loaded=1 errors=0`。

### 形态差异（写进文档，不是缺口）

上游写 `.ts`（jiti 运行时编译）→ 端口写 C#、预编译 `.dll`；入口是程序集里**恰好一个** public
`IExtensionEntry`（多个会抛，`FindEntryFactory` 明确不静默挑一个）。

### 顺带修的两处体验

1. 发现结果里的 `.ts/.js` 在进加载器前**分流成 warning**（带「编译为 dll」指引），同目录 `.dll`
   仍加载。注意：**不能在 `LoadExtensions` 内部拦**，那会破坏用 fake loader 喂 `.ts` 的 19 个测试。
2. `ResolveExtensionEntries` 优先 `index.dll`（同目录有源码 + 产物时只有能加载的算数）。
3. `Assets/examples/extensions` → `extensions-typescript`，README 顶部标明 protocol reference only；
   新增可编译示例 `samples/Pi.Sample.Extension`（工具 + 命令 + 状态栏，`Private=false`）。
