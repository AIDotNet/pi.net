### 发布踩的坑（关键）

**`dotnet nuget push "artifacts/*.nupkg"` 在 Windows runner 上必定失败**：
`dotnet nuget push` 自己不展开通配符，而引号又阻止 bash 展开，于是它把
`artifacts/*.nupkg` 当字面文件名 → `error: File does not exist (artifacts/*.nupkg)`。
修法：用 `for f in artifacts/*.nupkg artifacts/*.snupkg` 逐个推。
（首次因此在 Push 步骤失败两次，但 build/pack/上传 artifact 都成功了。）

**nuget.org 索引有 5-8 分钟延迟**：push 成功、GitHub Release 建好后，flatcontainer
仍 404 `The specified blob does not exist`，包页面也打不开。不要据此判断失败，
等 5 分钟再用 `api.nuget.org/v3-flatcontainer/<小写包名>/index.json` 复核。

### 写示例前必须搞清的真实 API（都是读源码确认的，不要凭印象写）

- `StreamFn` 是 `AgentOptions` 的 **required** 成员；委托签名
  `(Model, TranscriptContext, SimpleStreamOptions?, CancellationToken) → Task<IAssistantMessageEventStream>`
- **两个模型类型**：`Pi.Ai.Types.Model`（瘦记录，StreamFn 边界）与 `Pi.Ai.Models.ModelSpec`
  （目录条目，带 BaseUrl/ContextWindow/Cost）。`CompatShims.ToModel()` 是反向桥
- `Faux.Response` 是挂在 **`Faux`** 上而不是 `Faux.FauxResponseStep` 上
  （写 `Faux.FauxResponseStep.Response.Text(...)` 会 CS0117）
- `Pi.Mcp` 的传输在 `Pi.Mcp.Transports` 命名空间；`IMcpTransport` **没有** `Dispose`/`IAsyncDisposable`，
  收尾只能 `CloseAsync()`；`McpClient` 也没有 `Dispose`
- `AgentTool.Execute` 的 `args` 是 `object?`（实际是 JsonElement/JsonObject），
  统一用 `JsonSerializer.SerializeToElement(args)` 再取值最稳
- `AgentSession.Subscribe` 的监听器是**同步** `delegate void`，不能 `await`
- 配置路径：`~/.pi/agent/`（`Config.GetAgentDir()`，可被 `PI_CODING_AGENT_DIR` 覆盖）下有
  `auth.json` / `settings.json` / `models.json` / `mcp.json` / `skills/`；项目侧 `.pi/{settings.json,mcp.json,skills}`；
  `mcp.json` 顶层键是 `mcpServers`，**项目级只能覆盖 enabled/exposure/toolExposure，不能新增服务端**
- `mcp.json` 的 `exposure` 缺省是 `codemode`（不是 direct）——「连上了但模型不会用」就是这个
