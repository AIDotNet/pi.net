### 两个易踩的 C# 陷阱（写这批代码时踩到）

1. **`\x` 转义最多吃 4 位十六进制**：`"a\x00b"` 是 U+000B、`"\x07c"` 是 U+007C。测试里写控制字符
   要用 `\u0000` / `\u0007`。
2. `Regex.Replace(input, replacement, count)` 的 replacement 里 `$` 有替换语义，与 JS 的 `$&`
   规则不同——用扩展名/包名拼替换串时要留意。

### 推送踩坑（本机）

`git push` 走 Clash `127.0.0.1:7897` 时，schannel 后端报
`schannel: failed to receive handshake, SSL/TLS connection failed`；换成 openssl 后端即通：

```bash
GIT_SSL_BACKEND=openssl git -c http.proxy=http://127.0.0.1:7897 \
  -c https.proxy=http://127.0.0.1:7897 push origin main
```

`curl -x http://127.0.0.1:7897 https://github.com/` 返回 200 说明代理本身没问题，是 git 的 TLS 后端。

### watch 家族：上游把 durable 的 CommittedWatch 收进了 chord

1.5.0 起 `packages/durable/src/session/observation.ts` 已删除，`Watch<T>` / `NativeWatch<T>` 在
`packages/chord/src/watch.ts`（492 行），pending 折叠在 `packages/chord/src/delta/pending.ts`（173 行）。
端口落点：`src/Pi.Chord/Services/Watch.cs`（重写）+ `src/Pi.Chord/Delta/PendingOps.cs`（新），
`Pi.Durable/Session/Observation.cs` 只剩 `CommittedWatch<T> : Watch<T>` 一层薄适配。

语义变化（写代码时容易踩）：
- 监听器签名从 `(value, ops, context)` 变成 `(WatchCall<T>, context)`；`WatchCall.Value(value, ops, retired)`
  或 `WatchCall.Failure(error)`。
- `WatchEnd.Retired` 没了：退休是帧上的 `retired` 标记，不再结束 watch；`WatchEnd.Cancelled` 改名 `Aborted`。
- `endAfterDelivery()` 才是「投递完剩下的再结束」，`end()` 立刻丢弃待发内容。
- `Watch<T>` 折叠待发帧（一个忙碌周期一次调用）；`NativeWatch<T>` 每个值一帧、超 100 个折叠。
  **事件批次必须用 NativeWatch**，否则一批一帧的语义会丢（上游 `watchEvents` 就是这么写的）。

### 端口专有取舍

- 投递仍是 `Task.Run`（TS 是 `queueMicrotask`）。因此紧邻提交的循环会折叠成一帧，而 TS 恰好一提交一帧。
  受影响的断言：要么逐次 `FlushAsync`/`DrainedAsync`，要么改成断言「折叠后 ops 仍能推到最新值」。
- `Watch<T>` 多一个可选 `replace`（缺省与 TS 一致）。

### 两个 C# 细节

- 泛型类的构造函数不能写 `Watch<T>(...)`，只能 `Watch(...)`。
- `JsonSerializer.Serialize` 默认转义非 ASCII；测试里比较 JSON 要传
  `Encoder = JavaScriptEncoder.UnsafeRelaxedJsonEscaping`，孤立代理项仍会被转义（改成直接比字符串）。

  `detail.reason` 为 restart_limit|interrupted」→ 提交落地后 `_report`。`task_faulted` 那条路径
  （reserve 里 faulted 列表）仍然只报扩展种类，两者不重。
- 生成：`request`/`poll` 阶段见到 `Restarts != null` 就**记一次失败尝试**（`InterruptedAsync`）——
  partial 转 aborted、按 `settings.retry` 退避、轮询那次把 `poll{model,thinkingLevel,cutoff,handle}`
  塞进 `retry` 检查点，下一次再轮询同一 handle；没重试可用了才 `runFailure: interrupted`。
  其余阶段（prepare/tools）到限走 `EndCutOffAsync`（`runFailure: restart_limit`，`Salvageable` 决定是否
  再转换 partial / 取消延迟应答）。
- 工具：`EndCutOffAsync` 由槽拼错误结果（code `restart_limit`），**不过 afterTool**（钩子可能就是元凶）；
  `Ending` 加 `Reason`，failed 结局写 detail。
- 压缩：三阶段到限 `FailCutOffAsync`；`Live.compactionFailure` 这套「失败对客户端可见」的字段端口一直没做，
  本批补上（`FailCompactionStatus`/`DeleteCompactionFailure`，摘要产出时清）。
- `LiveSettle`：compaction 的 faulted 不再一律 remove，改为写 compactionFailure；被上限切断（只可能是
  abort 处理器）时保留「被中止」的含义——不写失败、运行以 `aborted` 收场且不转换 partial。

坑与教训：
1. **崩溃模拟必须逐次 Reopen**：`storage.Reopen()` 每次从**最初**那份克隆，循环里不更新变量就永远
   只计到 1 次重启（我用它调工具用例，`runs=3` 才暴露）。
2. 手工注入 `Restarts` 那条路（`((Transaction)tx).SetTask`）只适合「阶段检查」，真崩要靠不关闭 + Reopen。
3. 压缩要能出摘要：上下文得够长且**至少两轮**，`keepRecentTokens` 很小才切得出范围（只一轮切点是 0，
   等于没得压）。
4. 工具的部分输出要断言，得把 `progress.outputIntervalMs` 设 0，否则崩溃前还没落盘。

结果：新增 `HarnessRestartInterruptedTests` 5 例；`HarnessRestartTests`/`HarnessReportTests` 按新语义改写
