### 语料探针固化为可复跑回归测试

之前那次「71/86」是一次性临时脚本，已删。现在固化为
`tests/Pi.CodingAgent.Tests/UpstreamTypeScriptExampleTests.cs`：

- **口径**：顶层 `*.ts` + 各目录 `index.ts` = **79 个真实入口**；每个经
  `JsExtensionModuleLoader` 加载 → `ExtensionLoader.LoadExtensionFromFactory` →
  `ExtensionRunner` 派发 `session_start` → `tool_call`(bash) → `tool_call`(write) → `context`。
- **失败判定**：handler 异常走 `ExtensionRunner.OnError`，**必须订阅**才算数（不抛异常，
  只看派发是否抛出会漏掉全部 handler 错误）。
- **结果**：`clean=71 handler-fail=2 load-fail=6`；clean 的 71 个里 43 注册事件、16 注册工具、
  33 注册命令（合计 80 handlers / 30 tools / 54 commands / 3 flags / 2 shortcuts）——证明是真在干活。
- **回归保护是双向的**：`KnownFailures` 表与实际失败集做差集，新增失败红、已知失败转绿也红
  （提示收紧表格）。基线 `CleanBaseline = 71`。
- 8 个失败：4 个依赖未安装（`@anthropic-ai/sdk`、`@earendil-works/gondolin`、
  `@anthropic-ai/sandbox-runtime`、`ms`——这些目录有 package.json + lock 但 node_modules 被
  gitignore，上游也要 `npm install`）、2 个 provider 注册（`custom-provider-gitlab-duo` 的
  `registerProvider`、`jev-router` 的 `registerVirtualModel`）、`file-trigger.ts`（fs.watch）、
  `mac-system-theme.ts`（osascript，macOS 专用）。
- 另加 `NodeModuleResolution_ResolvesADependencyFromNodeModules`：手写 node_modules 假包，
  证明「缺依赖」是环境问题而非宿主解析缺陷（它一红，那 4 个就是宿主的锅）。

### 发布踩坑（下次直接照做）

1. **版本号有两处，只改一处会打包失败**：`Directory.Build.props` 的 `<Version>` 与
   `src/Pi.CodingAgent/Assets/package.json` 的 `version`。`Directory.Build.targets` 有校验，
   不一致时 `dotnet pack` 报 error——但**只在打 Pi.CodingAgent 时报错**，全量 `dotnet pack Pi.slnx`
   会静默少打 1 个包（13 → 12），CI 的「正好 13 个包」断言才会红。所以 pack 后一定要
   `ls artifacts/*.nupkg | wc -l` 数一遍。
2. **`dotnet test --filter` 对这个仓库无效**（MTP 平台会忽略 VSTest 属性）。改跑编译产物：
   `./Pi.CodingAgent.Tests.exe --filter-class "Namespace.ClassName"`（还有 `--filter-method`、
   `--filter-not-class`、`--show-live-output on`）。
3. **测试日志是 UTF-16**：`grep` 会当二进制文件。用
   `Get-Content <log> -Encoding Unicode | Select-String ...`（PowerShell）。
4. **flake 判定方法**：单独重跑该用例 3 次全绿即为 flake；若稳定红，先
   `git diff <上个 release tag> HEAD -- src/` 确认对应项目本次是否真被改动。
   本次全量 Release 测试 4 组失败全部是 flake（Pi.Ai 4 个、Durable 1 个、CodingAgent 1 个），
   且 1.4.4 之后只改了 `src/Pi.CodingAgent` 与 `src/Pi.Evals`，Pi.Ai / Pi.Durable 一行未动。
   `MistralStreamTests.AStreamThatOutlivesTheTimeoutKeepsGoing` 是环境依赖（HttpListener 头超时），
   干净 HEAD 上也失败。名单已补进 `docs/publishing.md`。
5. `git push origin main --follow-tags` 在本机**不会推 tag**（credential-manager 路径缺失导致
   tag 阶段被跳过，而 main 已推成功，容易误判）。必须补一次 `git push origin v1.4.5` 并用
   `git ls-remote --tags origin` 校验。
