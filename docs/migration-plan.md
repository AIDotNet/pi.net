7. **行尾敏感性**：本机 `core.autocrlf=true`，工作区 `.cs` 为 CRLF。C# **原始字符串字面量**（`"""`）会继承检出时的行尾，凡把它当作 `\n` 语料的测试都会在本机失败而在 LF 检出机上通过。根因是测试写法，不是移植缺陷。系统性修法是给仓库加 `.gitattributes`（`*.cs text eol=lf`）并 `git add --renormalize .`，但那会产生全仓重写 diff，暂不做，仅在此登记。**写新测试时一律用显式 `\n` 构造多行输入；多行常量用 `"""…""".ReplaceLineEndings("\n")` 归一。**

## 五、构建与测试基线问题（2026-10-12 修复）

本节记录本轮复核时发现、且**与移植语义无关**的仓库级问题，便于后续会话判断"失败是环境还是代码"。

### 5.1 `Pi.CodingAgent.Tests` 无法构建（阻断级）

- **现象**：`dotnet build Pi.slnx -m:1` 报 `CS0101`（`SelfRegisteredExtensions` 重复定义），清掉陈旧 `obj` 后转为 `CS0017`（多个入口点）。
- **根因**（两条，互相叠加）：
  1. csproj 里写的是 `XunitAutoGenerateEntryPoint`，而 xunit.v3 的实际属性名是 **`XunitAutoGeneratedEntryPoint`**（见 `xunit.v3.core.mtp-v1/buildTransitive/xunit.v3.core.mtp-v1.targets` 第 80/95 行的 `Condition`）。属性名写错 → 自动入口点照旧生成。
  2. `xunit.v3.core.mtp-v1.props` 把 `GenerateSelfRegisteredExtensions` 默认置为 `true`，于是 MSBuild 又生成一份 `obj/.../SelfRegisteredExtensions.cs` 并加入编译，与手写的 `TestEntryPoint.cs`（其中同时声明了 `SelfRegisteredExtensions`）冲突。
- **修法**：在 csproj 中把属性名改正为 `XunitAutoGeneratedEntryPoint`，并显式加 `GenerateSelfRegisteredExtensions=false`（与 `TestEntryPoint.cs` 顶部注释声明的意图一致：手写副本为唯一事实来源）。
- **注意**：修改后必须清掉 `tests/Pi.CodingAgent.Tests/obj` 里上一轮生成的 `SelfRegisteredExtensions.cs` / `XunitAutoGeneratedEntryPoint.cs`，否则陈旧文件仍会被编译。
