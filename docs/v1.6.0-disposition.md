## D. 2026-11-23 全量复核记录

对 62 条发布说明与 `edfe6b2ef..v1.6.0` 的 19 个提交做了一轮独立复核（不依赖上一轮的结论），
新发现并修复 2 个真实缺口，另有 1 处处置降级：

1. **`openai-codex` 目录缺 `supportsMidConvoEffort`**（真实缺口，已修）：上游 catalog 的
   `OPENAI_MID_CONVO_EFFORT_MODEL_IDS` 对 `openai` 与 `openai-codex` 两个 provider 都生效；
   端口 `openai.json` 的 7 个 GPT-6 模型有该标志，`openai-codex.json` 一个都没有。也就是说
   #12269 的 Codex 修复对真实模型**不会生效**（`GetConfigurationUpdateEffort` 恒为 null）。
   已在 `ModelData/openai-codex.json` 补上 7 个模型，并在 `ModelCatalogTests` 里对两个目录
   逐 id 断言，防止再次漂移。
2. **`models.schema.json` 改描述后未重生成文档**（真实缺口，已修）：CI 的
   `node scripts/gen-models-configuration.mjs --check` 会因 `docs/usage/models-configuration.md`
   过期而失败。已重新生成（2 行描述差异）。
3. **#39 一度降级为 ➖ 纯性能，随后补实现**：复核时确认端口只有 `RequestRender(bool force)`、
   `RenderLayoutFrame` 每帧新建 `LayoutContext` 并重渲染全部内容，没有上游 `requestViewRender()`
   的「滚动帧复用上一帧组件输出」（实测 20k 行 2.5–5.5 ms/帧、20k 单行组件 52 ms/帧）。
   现已按上游语义补齐：`LayoutRenderCache` 跨帧缓存组件输出，`TuiBase.RequestRender` 清缓存、
   新增 `RequestViewRender()` 不清；`TuiAltScreen` 的 `ScrollBy/Top/Bottom/Prompt` 与滚轮走
   view 回调，滚动条/尺寸变化/渲染期间失效各自清理。用例 `AltScreenViewFrameTests`（5 项，
   含「渲染中失效必须用空缓存重跑」）；实测 20k 行内容组件 1.45 → 0.41 ms/帧。

复核同时确认：#16/#18/#21/#29/#41 的「不适用」判定成立（.NET 无对应宿主形态），
`#54` 的证据按模型数更正（14 个 Responses + 3 个 completions），chord 两个 sync 提交
仍无消费方（`src/Pi.Chord` 无 `sync`/`Outbox`/`SyncBody`/`PullSession`）。
